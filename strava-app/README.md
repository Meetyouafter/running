# Strava Dashboard

Личный беговой дашборд поверх Strava API: активности, прогресс к целевому забегу, тренировочный план, AI-тренер, построение маршрутов.

## Что умеет

| Раздел | Описание |
|---|---|
| 📊 Дашборд | Список активностей, сводная статистика, объём по неделям, рекорды и прогноз на 5/10/21 км. Клик по активности — детали: сплиты, пульс, каденс, карта, интервалы |
| 🗓 План | Тренировочный план к целевому забегу, план vs факт по дням |
| ⏱ Темп | Калькулятор: дистанция + темп ⇄ время |
| 📈 Анализ | Готовность к старту, план vs факт, тренды, AI-разбор подготовки (Gemini) |
| 🏁 Забеги | Календарь стартов, свои отметки, импорт из Actiup |
| 🤖 Тренер | Чат с AI-тренером в контексте твоих пробежек, может править план |
| 🗺 Маршрут | Генерация маршрутов (OpenRouteService), популярные сегменты Strava, экспорт GPX |
| 🏆 Трофеи | Суммарная статистика Strava за год и за всё время |

## Запуск

```bash
npm install
cp .env.example .env   # заполнить ключи, см. ниже
npm run dev            # сервер :3001 + клиент :5173
```

Другие команды:

```bash
npm run build     # tsc + vite build → dist/
npm run preview   # предпросмотр сборки
npm run lint      # eslint, включая проверку FSD-границ
```

## Переменные окружения (`.env`)

| Переменная | Для чего |
|---|---|
| `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET`, `STRAVA_REFRESH_TOKEN` | Токен Strava (обязательно) |
| `GEMINI_API_KEY` | AI-тренер (серверный чат) |
| `ORS_API_KEY` | Генерация маршрутов, [openrouteservice.org](https://openrouteservice.org) |
| `ICU_ID`, `ICU_KEY` | Intervals.icu (опционально) |
| `PORT` | Порт dev-сервера, по умолчанию 3001 |

Ключ Gemini для AI-анализа на странице «Анализ» вводится в UI и хранится в localStorage.

## Как устроено

- **Клиент** — React 19 + Vite + TypeScript, состояние в zustand, роутинг react-router. Данные Strava кэшируются в localStorage.
- **Бэкенд** — тонкий прокси, чтобы не светить секреты в браузере: `server/` (Express, для `npm run dev`) и `api/` (те же хендлеры как Vercel serverless functions).
- **Структура `src/`** — Feature-Sliced Design: `app → pages → widgets → features → entities → shared`. Слой импортирует только нижние слои, слайс наружу отдаёт только `index.ts`, сущности общаются через `@x`. Правила проверяет `eslint-plugin-boundaries` (см. `eslint.config.js`).
